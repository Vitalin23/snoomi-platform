# QA-план: тест других нишевых каналов + проверка админки

Цель: перед прод-запуском убедиться, что система управляемая и понятная для клиента.

---

## 1) Тестовые ниши (обязательно разные)

Подготовить минимум 4 канала:

1. **Мебель/товары для дома** (e-commerce)  
2. **Локальные услуги** (салон/студия/сервис)  
3. **Экспертный блог** (психолог/коуч/преподаватель)  
4. **Нишевый инфоканал** (хобби/лайфстайл)

Платформы:

- минимум 2 Telegram + 2 VK (если есть доступы — больше)

---

## 2) Чеклист по клиентскому кабинету

## Шаг 1: Каналы

- [ ] ссылка/ник канала проходит проверку  
- [ ] имя и публичное описание подставляются после проверки  
- [ ] клиентское описание 20+ слов валидируется корректно  
- [ ] optional поле референсов (конкуренты/ориентиры) сохраняется  
- [ ] частота публикаций сохраняется  
- [ ] канал отображается в списке «Мои каналы»

## Шаг 2: Темы

- [ ] генерация тем отрабатывает  
- [ ] актуальные вопросы показываются релевантно (top-5)  
- [ ] темы сохраняются и повторно открываются после перезагрузки  
- [ ] ручные правки тем сохраняются

## Шаг 3: Календарь

- [ ] превью-календарь строится на нужное число постов  
- [ ] правки дат/времени/тем сохраняются  
- [ ] сохраненный draft открывается повторно

## Публикация

- [ ] «Опубликовать сейчас» работает для выбранных каналов  
- [ ] «Тест: 3 поста из плана» отрабатывает  
- [ ] Telegram с картинкой публикуется единым сообщением  
- [ ] VK публикация проходит без ручного вмешательства

---

## 3) Чеклист админки `/admin/clients`

## Управляемость

- [ ] создание/редактирование клиента  
- [ ] создание/редактирование пользовательского аккаунта  
- [ ] создание/редактирование подключения клиента  
- [ ] переключение активен/неактивен для подключений  
- [ ] ошибки форм отображаются понятно

## Контроль данных

- [ ] видно количество каналов по клиенту  
- [ ] корректно фильтруются подключения по выбранному клиенту  
- [ ] обновление карточек без ручного refresh (или с понятным refresh)

## Безопасность

- [ ] недоступно обычному клиенту  
- [ ] API админки защищены (`@admin_required`)

## Дашборд админа

## 5) Что добавить в админку после первого прод-теста

1. **Сводка ошибок публикаций по клиентам** (за 24ч/7д).  
2. **Состояние интеграций** (валидность токена, последнее успешное подключение).  
3. **Статус очереди/планировщика** (жив/не жив, последний цикл).  
4. **Retention по клиентам trial → активный тариф**.  
5. **Экспорт клиентских KPI в CSV**.

---

## 6) Формат прогона теста (рекомендуемый)

1. Заводим 4 тестовых клиента (по нишам).  
2. Каждому подключаем 1 Telegram + 1 VK (где возможно).  
3. Генерируем/редактируем темы и календарь.  
4. Запускаем `Опубликовать сейчас` и `Тест: 3 поста из плана`.  
5. Фиксируем:
   - успешные публикации,
   - ошибки с текстом ошибки,
   - качество текста/изображения,
   - читаемость интерфейса для “не-тех” пользователя.

Итог: таблица Pass/Fail + приоритетный backlog на доработки.
